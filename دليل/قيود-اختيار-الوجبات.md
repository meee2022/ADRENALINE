# قيود اختيار وجبات المشترك — المرجع الواحد (الويب + التطبيق + الخادم)

**القاعدة الذهبية:** كل قيد هنا مكتوب **مرة واحدة** في `shared/rules/` ويُستورد منه الثلاثة:
الموقع (`client/`)، تطبيق الجوال (`apps/mobile/`)، والخادم (`convex/`). لا قاعدة تُكتب داخل شاشة.
الخادم هو الحكم الأخير: يعيد التحقق عند إنشاء الطلب ويرفض المخالف مهما كانت الواجهة.

> آخر مراجعة متحقَّقة: ١٢ سبتمبر ٢٠٢٦ — الاختبارات `npm run check:rules` (١٤ حالة) ناجحة،
> وفحص الأنواع للويب والتطبيق ناجح.

## القيود الـ١٣

| # | القيد | الدالة في `shared/rules` | الخادم يرفض بـ |
|---|---|---|---|
| ١ | **عدد الوجبات والسناك يومياً**، و**صفر يعني صفر** (مشترك بلا سناك لا يفتح له سناك). غير المسجَّل = بلا حد | `dailyLimits` · `dailyLimit` (`selection.ts`) | `SUBSCRIPTION_COUNT_MISMATCH` |
| ٢ | **السلطة تُحسب سناك**، والرئيسية = فطار/غداء/عشاء | `isSnackCategory` · `isMainCategory` (`mealSchedule.ts`) | `INVALID_CATEGORY` |
| ٣ | **أيام الاشتراك**: من بكرة (بيوم قطر)، السبت→الخميس، تخطّي الجمعة، والدورة تتقدّم +١ كل جمعة (تلفّ ١..٤)؛ **بداية يوم جمعة لا تتقدّم مرتين** (مُصلَح 2026-09-12) | `orderedSubscriptionSlots` · `subscriptionSlotKeys` (يمرَّر لها `todayISO`) | `SLOT_OUTSIDE_SUBSCRIPTION` · `INVALID_SLOT` |
| ٤ | **تسلسل الأيام**: لا يُفتح يوم قبل اكتمال اليوم السابق | الويب: `firstIncompleteIdx` في PublicMenu · التطبيق: `pickVerdict → previousDayIncomplete` (كلاهما على `dayComplete`) | — (قيد واجهة) |
| ٥ | **الوجبة مجدولة لهذا (الدورة + اليوم)** فقط؛ بلا جدولة لا تُعرض | `mealAvailableOn` · `mealScheduledFor` | `MEAL_NOT_SCHEDULED` |
| ٦ | **الممنوعات والحساسية**: تُسمّى الكلمة المخالفة (TURKEY / NO SALT) وتحتاج تأكيداً صريحاً، ويظهر التنبيه للأخصائية | `restrictionWords` · `restrictionHit` · `avoidTokens` (`mealRestrictions.ts`) | — (تأكيد لا منع) |
| ٧ | **فطار ثانٍ في نفس اليوم**: مسموح بتأكيد صريح ويُحسب من الرئيسية؛ الاختيار التلقائي (الذكية/الإكمال) يبقى على فطار واحد | `addMealVerdict.secondBreakfast` · `BREAKFAST_MAX_PER_DAY` | — |
| ٨ | **تكرار نفس الصنف في نفس اليوم** بتأكيد صريح | الويب: `itemCount` · التطبيق: `pickVerdict.duplicate` | — |
| ٩ | **الاشتراك الموقوف أو المنتهي لا يطلب** («لم يبدأ بعد» ليس موقوفاً) | `subscriptionState` (`subscription.ts`) · التطبيق: `selectionState.paused` | `SUBSCRIPTION_PAUSED` · `SUBSCRIPTION_EXPIRED` |
| ١٠ | **لا إرسال قبل اكتمال كل يوم** بعدد الاشتراك بالضبط | `subscriptionShortfall` · `dayComplete` · `planShortfall` | `SUBSCRIPTION_COUNT_MISMATCH` |
| ١١ | **الخطة الذكية** تمرّ من نفس الفلاتر قبل قبول أي اقتراح (حجب، سقف الفطار، حدود اليوم) | `convex/ai.ts` يستورد `restrictionWords/mealIsRestricted/BREAKFAST_MAX_PER_DAY` · التطبيق: `mergeSmartSuggestions` | — |
| ١٢ | **الإرسال بنفس الدالة** `customerOrders.create` بمفتاح idempotency يمنع تكرار الطلب عند انقطاع الشبكة، والخادم يطابق الرقم بالهوية | `convex/customerOrders.ts` · `convex/lib/customerOrderRules.ts` | `CUSTOMER_IDENTITY_MISMATCH` · `RESTAURANT_MISMATCH` |
| ١٣ | **الخادم يعيد التحقق** بكل ما سبق (`validateCustomerOrderSelection`) ويكتب السعرات والأسماء من الكتالوج لا من الواجهة | `convex/lib/customerOrderRules.ts` | كل الأكواد أعلاه |

**فرق مقصود واحد:** مشترك مسجَّل **بلا أعداد** (لا وجبات ولا سناك): التطبيق والخادم يمنعانه
(`SUBSCRIPTION_COUNTS_MISSING`)، أما الويب فيعرض له تحذير «لم يتم تحديد عدد وجباتك» ويمنع الإضافة
(`noMealPlan`). النتيجة واحدة: لا طلب حتى تضبطه الأخصائية.

## أين تعيش القواعد في الكود

| الملف | ماذا فيه |
|---|---|
| `shared/rules/mealSchedule.ts` | التصنيفات، سقف الفطار، أيام التوصيل، `mealScheduledFor`، `mealAvailableOn`، `localISO` |
| `shared/rules/subscription.ts` | حالة الاشتراك، `orderedSubscriptionSlots`، `slotToDate`، `planShortfall`، `subscriptionShortfall` |
| `shared/rules/selection.ts` | الحدود اليومية، عدّ اليوم، الاكتمال، `addMealVerdict`، `slotFull`، `subscriptionSlotKeys` |
| `shared/rules/mealRestrictions.ts` | كلمات المنع، المطابقة، فحص الوصف |
| `shared/rules/nutrition.ts` | معامل البرنامج (غداء/عشاء فقط) والسعرات من الماكروز ٤/٤/٩ |
| `client/src/pages/public/PublicMenu.tsx` | الويب: يعرض الرسائل فقط ويستورد الحكم |
| `apps/mobile/src/subscriberSelection.ts` + `smartSelection.ts` | التطبيق: تنسيق الشاشة فقط، الحكم من `shared/rules` |
| `convex/lib/customerOrderRules.ts` | الخادم: `validateCustomerOrderSelection` |
| `scripts/check-rules.ts` | ١٣ حالة اختبار من مشاكل حقيقية سابقة |

## لو حصلت لخبطة — خطوات الرجوع بسرعة

1. **شغّل الاختبارات أولاً**: `npm run check:rules`. لو انكسرت حالة، اسمها يقول أي قيد اختلّ.
2. **اعرف من يستورد القاعدة** قبل أي تعديل:
   ```bash
   grep -rn "shared/rules\|lib/subscription\|lib/mealSchedule\|lib/mealRestrictions" client convex apps/mobile/src
   ```
   المستوردون الحاليون: PublicMenu، SmartPlan، OrderReview (العميل)، OrderReviewDetail (الأخصائية)، Plans،
   convex/ai، convex/lib/customerOrderRules، apps/mobile/src/rules.ts.
3. **اختبر على الخادم مباشرة** (تطوير) أن الرفض يعمل:
   ```bash
   npx convex run customerOrders:create '{"customerName":"t","customerPhone":"00000000","items":[{"mealId":"<id>","week":5,"day":"friday"}]}'
   ```
   المتوقع: `ORDER_VALIDATION:INVALID_SLOT`.
4. **ارجع لآخر نسخة سليمة**: commits القواعد المتحقَّقة `af7de43` → `1264ac7` → `192e885`.
   `git revert <commit>` ثم `npx convex deploy -y` للخادم، والويب يُنشر بالرفع.
5. **لا تُصلح قاعدة داخل شاشة**. أصلحها في `shared/rules` وأضف حالة اختبار لها في `scripts/check-rules.ts`.
