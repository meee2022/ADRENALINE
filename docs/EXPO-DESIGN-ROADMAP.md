7. عرض المدة وعدد الوجبات والسناك وأيام التوصيل والسعر النهائي واختيار الباقة بوضوح.
8. فصل رئيسية الزائر التسويقية عن رئيسية المشترك العملية: وجبات اليوم، موعد إغلاق التعديل، التوصيل، الأيام المتبقية، والأخصائية.

## مناطق حساسة وبوابة التحقق

المصدر المشترك هو `shared/rules`، مع تحقق الخادم القائم. لا نسخ لقواعد العمل داخل مكونات Expo.

قبل نقل اختيار الوجبات، تتبع أيضاً القواعد الموجودة خارج المجلد المشترك في الويب والخادم؛ لا تفترض أن الاختبارات الحالية تغطيها كلها.

قائمة حالات التكامل المطلوبة على بيئة اختبار منفصلة:

- صفر سناك، حدود الوجبات والسناك، السلطة ضمن السناك، وحالة الفطار الثاني.
- اشتراك غير نشط أو منتهي أو موقوف، وأعداد مفقودة؛ تثبيت السلوك الحالي قبل نقله.
- بداية ونهاية الاشتراك، دورة الأسبوع الرابع إلى الأول، الجمعة، وتوقيت قطر وحدود موعد التعديل.
- توفر الوجبة في أسبوع الطبخ واليوم المختارين، والجدولة الحديثة والقديمة.
- الحساسية والممنوعات والتفضيلات، ومعامل البرنامج وحساب التغذية.
- حفظ وإزالة واستبدال الوجبات، إعادة فتح التطبيق، ضعف الشبكة والنقر المتكرر وتعارض تعديلين.
- رفض الخادم للاختيار غير المسموح؛ لا الاعتماد على إخفاء زر فقط.
- عدم تأثر صفحات المطبخ والتوصيل والأخصائية والتقارير بالبيانات الناتجة.

### لكل خطوة

1. وصف الملفات المسموح تغييرها والسلوك الذي يجب أن يبقى كما هو.
2. مراجعة المستوردين وعقود البيانات، ثم اختبارات قبل التغيير.
3. تعديل محدود قابل للتراجع، دون إعادة هيكلة أو تحديث اعتماديات جانبي.
4. `npm run check:rules` و`npm --prefix apps/mobile run typecheck`؛ إضافة اختبارات مناسبة للنطاق قبل تغيير سلوك حساس.
5. فحص العرض وRTL وحجم الخط واللمس على الجوال. معاينة الويب وحدها ليست اعتماد Android/iOS.
6. مراجعة diff وتسجيل نتيجة الاختبارات وما لم يُختبر، ثم عرض النتيجة للمستخدم. لا نشر تلقائي.
